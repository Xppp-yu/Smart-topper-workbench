# 团队文件接收与验收清单

## 1. 接收登记

- [ ] 记录发送人、接收日期、版本或任务名称。
- [ ] 原始文件保存在 `E:\创业\团队文件接收与项目推进存档`。
- [ ] 记录核心文件 SHA-256。
- [ ] 保存原始 README、运行命令和预期输出截图。
- [ ] 原件不直接修改。

## 2. 环境识别

- [ ] 确认来源系统：Windows、WSL、Linux 或 macOS。
- [ ] 确认 Python 版本。
- [ ] 查找 `requirements.txt`、`pyproject.toml` 或 `environment.yml`。
- [ ] 不复制来源项目的 `.venv`。
- [ ] 不把新依赖安装进 Windows Anaconda `base`。

## 3. 代码审阅

- [ ] 检查是否写死个人绝对路径。
- [ ] 检查矩阵方向，统一写明 `(rows, columns)`。
- [ ] 检查标签定义和 `UNKNOWN/REJECT/EMPTY` 的区别。
- [ ] 检查 `sample_id` 是否跨文件唯一。
- [ ] 检查异常是否被静默跳过。
- [ ] 检查随机种子和数据划分是否可复现。
- [ ] 同一受试者不得同时进入训练集和测试集。

## 4. 最小运行验收

- [ ] `uv sync --python 3.12` 成功。
- [ ] 环境健康检查通过。
- [ ] `uv run pytest -q` 通过。
- [ ] 至少一条真实数据可以读取。
- [ ] 至少一张压力图可以生成。
- [ ] 输出目录、文件名和数据版本可追溯。

## 5. 算法结果验收

- [ ] 训练、验证、测试按受试者隔离。
- [ ] 模型选择只使用验证集，测试集只做最终验收。
- [ ] 同时报告 Macro-F1、混淆矩阵和逐受试者指标。
- [ ] 保存逐样本预测、置信度和错误样本。
- [ ] 软件降采样不得直接宣称等于真实硬件密度验证。
- [ ] 公开数据结果不得宣称为自研传感器、控制闭环或产品效果验证。

## 6. 交付内容

- [ ] README 包含从零运行命令。
- [ ] 依赖和 Python 版本已锁定。
- [ ] 配置文件不包含个人隐私路径或密钥。
- [ ] 结果报告注明数据、代码版本、随机种子和限制。
- [ ] Git 工作区无不明大文件和环境目录。
